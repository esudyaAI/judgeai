# Вердикт — фронтенд (моки)

Вёрстка канваса «Вердикт — ИИ-помощник судьи»: лендинг и личный кабинет (новое дело → материалы → анализ → результат, настройки). React 19 + Vite 7 + TypeScript, без UI-библиотек и роутера. Все данные — моки.

## Запуск

```bash
npm install
npm run dev        # http://localhost:5173
npm run build      # tsc -b && vite build → dist/
```

Node: `>=22.13.0` (PDF.js); для `npm test` используйте Node22.18+ или24.

## Маршруты

| Путь | Экран |
|---|---|
| `/` | Лендинг |
| `/app` | Кабинет — готовый проект (дело c1) |
| `/app/new` | Новое дело |
| `/app/attach` | Материалы загружены |
| `/app/case/<id>/analysis` | Идёт анализ (через 4,6 с → результат) |
| `/app/case/<id>/result` | Результат по делу |
| `/app/settings` | Настройки |

Для прод-хостинга нужен SPA-fallback на `index.html`. `vite dev` и `vite preview` делают его сами.

## Структура

```
src/
  api/          types.ts — доменные типы; mock.ts — данные из макета; client.ts — единая точка доступа (сюда подключать бэкенд)
  components/   Logo, Icon, FileTile, SentenceScale (шкала «Сверка с законом»)
  hooks/        motion.ts — in-view, count-up, таймлайн демо, scroll-reveal
  landing/      Nav, Hero+Marquee, Demo (15-секундный сценарий), Sections, landing.css
  cabinet/      Cabinet (состояние + URL), Sidebar, Composer, screens, Settings, cabinet.css
  styles/       tokens.css (цвета/радиусы/easing из макета), shared.css, global.css
scripts/        sandbox-build.mjs, spa-serve.mjs — только для проверки без npm, в рабочий процесс не входят
```

## Подключение к бэкенду (judgeai/judgeai)

`vite.config.ts` проксирует `/api` → `http://localhost:8000`. Соответствие сущностей:
- дело ↔ `Chat`: `GET/POST /api/chats`;
- материалы ↔ `Attachment`: `POST /api/chats/{id}/messages` (multipart `files[]`, `content`);
- результат ↔ `Message.analysis`. **Формат `analysis` с бэкендом не согласован**: UI ждёт структуру `CaseAnalysis` из `src/api/types.ts`.

Что требует API, которого в бэкенде нет: этапы анализа в реальном времени (сейчас таймер), скачивание `.docx`, поиск по делам, авторизация, профиль, сеансы, экспорт и удаление данных. Все такие места помечены `TODO(api)`.

## Отличия от макета (осознанные)

- **Мобильная навигация лендинга (≤960 px).** В макете ссылки переносятся в «пилюлю» в 2–3 строки. Здесь остаются логотип, «Войти» и «Попробовать».
- **Сайдбар кабинета на телефоне (≤760 px).** В макете он просто скрыт, и вернуться к списку дел нельзя. Здесь это выдвижная панель по кнопке ☰.
- **Число страниц на экране «Материалы».** Считается из файлов: 38+61+2+1 = 102. В макете написано 113, это расхождение внутри самих моков.
- **Рабочие элементы вместо картинок.** Поле ввода — настоящий `<input>`, файлы можно выбрать или перетащить, удалить файл из списка тоже можно.

## Известные вопросы по доступности (цвета не менял, они из макета)

Контраст по WCAG, порог для мелкого текста — 4.5:1:
- `#adadad` на белом — **2.24:1**. Это ожидающие шаги анализа и невыполненные строки в бенто.
- `#8a8a8a` на `#f0f0f0` — **3.03:1**. Это плейсхолдеры в полях ввода.
- `#707070` на `#f3f3f3` — **4.46:1**. Это мета-строки в сайдбаре и подписи в серых карточках; на белом этот же цвет даёт 4.95:1, это норма.
- Минимальный фикс: сдвинуть muted до `#6b6b6b`, subtle — до `#767676`.
- Плейсхолдеры контента: `[НАЗВАНИЕ КОМПАНИИ]`, `[УТОЧНИТЬ …]`, `[Имя пользователя]`, `[Регион]`, `[дата]`, `[Город]`.
