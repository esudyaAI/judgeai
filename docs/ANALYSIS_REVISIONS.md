# Сохранённые расчёты и история версий

Требования полного human-review — `superpowers/plans/2026-11-04-fact-review.md`; все статусы/проверки/остатки — `TASKS.md`.

## Контракты calculation-inputs/1, /2, /3 и /4

`infrastructure.calculation_inputs` переводит фактические аргументы существующей `assemble_analysis` в самостоятельный JSON-снимок. В нём зафиксированы `engine_version`, модельные факты с цитатами, prompt/полные извлечённые тексты, extraction coordinates/attachment hashes, sentence, sanctions+editions, практика/episode reports/candidate pools, предупреждения и provenance. Составные ключи count_statutes сохраняются списком reference/reading; даты/enums/sets нормализуются во внешнем adapter, наборы сортируются. Запись не содержит upload paths/ключей провайдера.

Новые снимки `/2` дополнительно содержат `kwargs.prepared_legal_inputs`: полную карту осуждённых с подготовленными цитированными входами ст.15/18. Один осуждённый — индекс0, несколько — индексы scoped subjects. Явно переданная карта должна содержать все ожидаемые индексы. Unknown в ней не дополняется из raw text/model; числовые1/0 не превращаются в boolean. Эти значения ещё не являются human decisions: проверяющий/причина/проверенная привязка цитаты к координатам добавляются отдельным review use case.

`services.legal_checks` отбирает primitives с дословной цитатой и переводит результат в DTO (совпадение цитаты не доказывает смысловую корректность факта или применимость редакции); `domain.prepared_legal` не зависит от framework/regex/БД и вызывает существующие core categorize/classify_recidivism. Доменные вычисления сохраняют отличие False от unknown, неполную историю, отдельность приговоров и конфликт с указанием суда. Остальные нормы всё ещё подготавливают часть данных внутри assembly; полная clean architecture этим этапом не заявляется.

Новые снимки `/3` дополнительно содержат `kwargs.prepared_sentencing_inputs` по осуждённым: обогащённое назначение (основное/дополнительные, даты/неотбытая часть/зачёт), проверенные дословными court findings обстоятельства, основание отсутствия отягчающих, ссылки ст.64 по эпизодам и входы режима/пола/прежнего отбывания. Calculation использует эти значения без повторного поиска в исходном тексте. Clearing не превращается обратно в regex value. Для ранее указанного, но теперь неизвестного режима выдаётся insufficient_data; отсутствие исходного указания сохраняет прежнее отсутствие такой проверки.

Отсутствие подтверждённого исключения не является утверждением о его юридической неприменимости: core продолжает применять прежнюю консервативную eligibility логику, а результат остаётся предварительным. Неизвестные flags в подготовленных данных не подменяются подтверждённым False. Known circumstances требуют цитату; поле term.amount сохраняет целое/дробное представление в новом codec/3, чтобы восстановление не меняло объяснение «48 мес.» на «48.0 мес.». Исторические codecs/1,/2 сохраняют прежний числовой decoder.

Для `/3` обе полные карты обязательны; отсутствие карты или не тот набор осуждённых отклоняется. Exception tuples должны соответствовать количеству эпизодов. Это trusted internal data, а не готовая форма редактирования: строгая проверка человеческой команды/источника/координат/причины/actor и optimistic base ещё нужна.

Новые `/4` дополнительно сохраняют `review_sources`: SHA-256 извлечённых текстов, labels/индексы осуждённых и разрешённые интервалы исходников. Полные тексты остаются в frozen kwargs и не дублируются в metadata. Интервалы считаются в Unicode codepoints Python str, не UTF-8 bytes/JS UTF-16 units. Чтение источника/проверка цитаты использует сохранённую карту без запуска текущего scoper или чтения attachment файла.

Для multi-person допустимы явно отнесённые intro/description statements и индивидуальные operative blocks. Неотнесённый префикс не отдаётся первому лицу; явно common statement может относиться к обоим. При коллективном назначении без индивидуальных блоков такое назначение не превращается в индивидуальную область доказательства. Вопрос пользователя доступен для цитирования лишь single context. Это консервативная область вычисления, а не доказательство смысловой/юридической истинности факта.

`GET .../revisions/{id}/sources` возвращает owned snapshot texts/context. `POST .../revisions/{id}/evidence/check` (CSRF) принимает subject_index и document_index/hash/start/end/quote, проверяет дословность/границы/область и возвращает source_matches. Операция не создаёт revision и не меняет human_review. Будущая команда review обязана заново вызвать этот же validator под case lock и не доверять successful preflight клиента. Чужие404; старые/1–/3 без зафиксированной карты409 с предложением нового анализа; неверные evidence422. Историческая attribution карта текущим parser не backfill-ится. Результаты/старый replay сохраняются.

Старый `/1` без prepared map продолжает использовать прежнюю подготовку из сохранённых raw inputs. При просмотре уже сохранённой версии её JSON не изменяется и новая карта не backfill-ится в историю.

Replay проверяет версию контракта и движка, восстанавливает типизированные значения и вызывает ту же assembly. Он не читает текущую БД санкций/практики и не вызывает LLM/embedding/search. Другая версия движка отвергается, а не исполняется текущим кодом под старой меткой. Это снимок существующего calculator; ст.15/18 и sentencing preparation получают явные данные; часть orchestration/DTO mapping остаётся в services, human decisions ещё не реализованы. Сам snapshot не означает подтверждение фактов.

## История и транзакции

`analysis_revisions` хранит самостоятельные calculation_inputs/result JSON с SHA-256, per-message version, predecessor, kind и review metadata. Новый machine результат и текущее Message.analysis сохраняются одной транзакцией. В result добавлены revision metadata и `human_review.status=not_reviewed`; API сообщений остаётся совместимым, id исходного assistant message при recalculate не меняется.

Перед очисткой result в POST recalculate архивируется прежний результат, если он ещё не совпадает с сохранённой версией. Для старых/неполных результатов используется kind=legacy, inputs=NULL и unknown review при отсутствии записанной проверки. Текущие настройки не восстанавливают фиктивные inputs. Если новый анализ или сохранение версии падает, прежняя история остаётся; незакоммиченная новая версия откатывается. Повторное выполнение настоящего анализа создаёт следующую версию; защита от двойной доставки одного job относится к T18, идемпотентные human commands — к следующему этапу T13.

Снимки готовых отчётов/DOCX самостоятельны и не следуют за текущим Message.analysis. Удаление дела/аккаунтных дел удаляет его версии по FK cascade; чужие записи остаются. Account export включает принадлежащие пользователю inputs/results/history без файловых путей.

## Read API

- `GET /api/chats/{chat}/messages/{message}/revisions?limit=50&offset=0`: summary, новые версии первыми, limit1..100/offset>=0. Summary-запрос не загружает полный JSON inputs/results.
- `GET .../revisions/{uuid}`: сохранённые inputs/result/review/hash. Перед выдачей проверяется целостность; повреждённый снимок409. У legacy inputs могут отсутствовать.
- Обе операции проверяют owner чата и assistant message; чужой/неподходящий источник404. Ответы private/no-store. GET не запускает пересчёт и не делает внешний запрос.

Это API хранения/истории. Форма подтверждения/исправления, POST review, replay исправленных фактов и UI просмотра предыдущей версии ещё не реализованы. Наличие nullable client_request_id/payload hash в схеме не означает готовность идемпотентной команды review.

## Миграция0016 и откат

План подготовлен до реализации. Миграция добавляет таблицу без backfill старых результатов; populated downgrade отказывается до явного архива, offline downgrade без проверки также отказывается. Предыдущее приложение игнорирует дополнительную таблицу, SQL downgrade для отката приложения не нужен. Рабочее применение требует отдельного разрешения/backup/restore; инженерные проверки выполняются только в isolated test DB.

Производственный профиль ресурсов/нагрузки не принят. Снимок включает полные материалы и candidate pools ради последующего проверяемого расчёта; будущие ограничения очереди и измерения T18 нельзя заменять коротким синтетическим тестом.

Human review command (локальная реализация T13)

`GET .../revisions/{id}/facts` возвращает allowlisted catalog фактических prepared inputs с subject, типом, допустимыми значениями и старой цитатой. `POST /api/chats/{chat}/messages/{message}/review` принимает `base_revision_id`, UUID `client_request_id` и 1–200 decisions (`fact_id`, `operation=confirm|correct|unknown`, `reason`, optional строгое string/bool `value`, optional `evidence` прежнего source-контракта). Actor/time берутся сервером. Произвольный JSON path и actor клиента запрещены. Confirm не принимает новое значение и требует существующее known; correct требует typed known value и точную цитату; unknown требует причину и не принимает value/evidence. Unknown остаётся null, False остаётся False.

Реализованы guilt (оба связанных входа без regex fallback), category/real/history, все поля уже существующих prior rows, court-stated recidivism, regime/male/served, no-aggravating и art64 per count. Начальный scalar catalog расширен назначениями/единицами/датами/conditional/circumstances и append prior/count; подробности ниже. Полный T13 остаётся открытым для fine-credit editing, practice refilter, editor/history/source picker и DOCX выбранной версии. Старые inputs/1–/3 читаются/replayable, но human review требует /4 и текущую версию engine; attribution не создаётся задним числом.

Case lock сериализует review с send/recalculate/delete. После owner-проверки повтор той же команды возвращает тот же immutable result даже после последующих версий/появления busy. Другой payload с тем же owner/request key, stale base или busy дают409. Неизвестные поля/неверные types/цитаты/лицо дают422, чужие404. Revision row и current Message пишутся одной транзакцией; сбой, в том числе после flush INSERT, откатывает оба и позволяет повторить тот же request UUID. SQL schema0016 уже содержит нужные request/hash поля; отдельной миграции и backfill нет.

Human version хранит накопленные решения с actor/time/base/reason/old/new/field label/evidence; status всегда `partially_reviewed`, legal_approval=false. Row.review должен совпадать с hashed result.human_review. При фактическом изменении входов удаляются старые LLM variants/recommended term, машинная сводка заменяется явной ссылкой на предыдущую версию. Сохранённая practice query/candidate pool остаётся в immutable inputs, но additive `review_invalidations=["practice"]` запрещает replay показывать старую статистику/прецеденты. Current analysis и отдельный raw-text practice endpoint не выдают прежнее сравнение как новое. Это промежуточная инвалидация перед автоматическим frozen-pool refilter, описанным ниже; до завершения refresh прежняя статистика не выдаётся как актуальная. Confirm без изменения вычислительных значений сохраняет сравнение; перевод text-derived guilt в known model input считается изменением.

Reports сохраняют читаемый статус частичной проверки и журнал решений/цитат. Старые report bytes неизменны; экспорт произвольной исторической revision ещё не реализован. Frontend fact editor/history/source picker также остаются работой T13.

Расширенный catalog назначений

Human command также принимает structured `value` для term (`kind`, `amount`, `unit`), circumstance (`name`, `norm`, `established`), missing prior (allowlisted core fields; `judgment_id` обязателен; отсутствующие поля unknown) и missing count (`qualification`, `main`, optional `additional`, `stage`, `offence_date`). Numeric/bool/string типы проверяются без coercion: bool не amount/int, дробный испытательный срок недопустим, NaN/Infinity/неположительные суммы отвергаются. Fine — rubles, compulsory works — hours, временные виды — months/days; life/death не принимают величину. Known kind с неизвестной величиной — amount/unit=null; unknown whole term — отдельный маркер, отличный от известного вида.

В catalog доступны `sentence/count/{i}/main|qualification|stage|offence_date|guilt`, additional entries/new, `sentence/final|intermediate|unserved|joined|credited`, conditional/probation_months/prior_judgment_date/aggregation_rule/intermediate_rule, absorption/final|intermediate; circumstance/mitigating|aggravating/{i}|new; prior/new; sentence/count/new и final_additional entries/new. /new добавляет запись в конец, не перенумеровывает старые IDs. Поле определяется только server catalog; существующие confirm/correct/unknown и source binding действуют на все новые типы.

В inputs/4 additive PreparedSentencingInputs: unknown_fields, guilt_by_count, aggregate_absorption; у circumstances established=True|False|None. Это private JSON в существующей0016, без SQL/backfill. Snapshot без новых frozen guilt/absorption остаётся replayable, но для human review требуется новый анализ: текущий parser не приписывает старой версии новые подготовленные входы.

При unknown main в core остаётся latent исторический term, явно закрытый unknown_fields: соответствующий count check/ст.68 и зависимая совокупность не вызываются с этим значением, Result не показывает его вид/срок как known. Unknown additional аналогично блокирует соответствующую проверку, итог additional и присоединение ст.70, зависящее от вида. Unknown conditional выдаёт null в presentation и insufficient для выбора ст.73/58; False остаётся False. Unknown circumstance хранится как запись established=null, не превращается в доказанное отсутствие. Unknown stage даёт stage_conflict, даты/optional terms/rules очищаются; их неизвестность видима в metadata/представлении. Независимые count/legal проверки остаются доступными.

Форма вины для ст.69 и способ поглощения замораживаются отдельно; человеческие решения не восстанавливаются из исходного текста. Общая correction guilt обновляет model/category/per-count входы; отдельный guilt эпизода меняет вход совокупности. При смене qualification reference меняется тем же действием, старый root sanction/model maximum/qualification снимается, возможна только совпадающая frozen count sanction. При смене offence_date в snapshot нет достаточной temporal metadata редакции; `statute/{count}` блокирует её применение в соответствующем subject до новой сверки, без обращения к текущей БД законов.

DOCX audit форматирует structured term/record по-русски, сохраняет причины/цитаты/actor/time; Result и DOCX явно показывают unknown conditional и назначения. Fine-credit facts и frozen-pool refilter описаны ниже. Полноценные UI editor/history/source picker и DOCX выбранной исторической версии остаются работой полного T13.

Fine-credit records и повторный отбор практики

`sentence/fine_credit/{index}|new` принимает object scope/count_index/original_amount/reduced_amount/released/status. Scope — count|final|unassigned; только count принимает существующий strict integer count_index. Обе суммы конечные неотрицательные numeric|null, reduced не выше known original; released strict bool, при released=true reduced=null|0, status=stated|requires_review. Это запись решения суда: human correction не рассчитывает дни→рубли и не подтверждает законность зачёта. Unknown whole-record сохраняет latent core запись и её индекс с `unknown_fields=fine_credit/{index}`; в presentation unknown=true, amounts/released=null, scope=unassigned, status=requires_review. Калькулятор совокупности по-прежнему не делает неподдерживаемый автоматический расчёт штрафного зачёта. Result/DOCX показывают, что сведения не установлены; False, неизвестное и освобождение остаются различимы.

POSTreview после synchronous replay автоматически выполняет asynchronous frozen-pool refresh и только затем сохраняет новую revision/current Message атомарно. `review_invalidations=[practice]` теперь промежуточное состояние калькулятора. Исходные per-subject PracticeReport сохраняются один раз в additive root `review_practice_baseline` inputs/4; `.kwargs.practice/defendant_practice` после refresh содержат только актуальные результаты отбора. Новый refilter использует тот же исходный bank, даже если предыдущая правка исключила из текущего результата часть кандидатов. Чужой/global multi-person pool не заполняет missing own subject bank. При отсутствии full candidate_pool возможен только показанный ранее список, что записывается basis=shown_only и отдельным ограничением. Нет backfill/SQL migration/нового поиска.

`review_practice_refresh={version:frozen-practice-review/1,subjects:{...}}` фиксирует refiltered|unavailable, pool_size, basis и vector_used=false. Копия trace входит в provenance.practice_review; старые LLM/model receipts остаются исходными. Human review practice_invalidated отражает unavailable subjects, а не запускает повторный корпусный запрос. No-network adapter возвращает только frozen StoredCard; embedder возвращает None. Существующий compare_draft_with_practice/FindSimilarPrecedents повторяет действующие core filters/ranking/statistics на полном сохранённом pool (optional statistics_pool, default50 для обычного поиска), без второго набора расчётов. Min/max/draft comparison допускают fractional months, включая15days→0,5month; формат и арифметика core не округляются до integer cache.

Query строится из исправленных prepared qualification/term/circumstances/conditional/fine credits и новых recidivism checks; старый frozen fabula сохраняется лишь как прежний текстовый контекст, 64/73 берутся из исправленных входов. Явно unknown conditional/circumstance/fine credit и нераспознанная qualification/norm делают comparison unavailable, не False/доказанное отсутствие. Known kind с unknown quantity может дать statistics без позиции проекта. Стадия преступления и временная применимость закона не входят в действующие matching filters; ограничение явно выводится. Ранее исключённые исходным поиском и новые карточки корпуса не восстанавливаются из ничего. Старые model variants/recommended term не возвращаются.

GET /api/chats/{id}/precedents после human version читает только её integrity-checked frozen report, учитывает own subject и limit1..50 (показанные карточки, затем оставшиеся retained candidates). Ни свежий SqlPrecedentStore, ни model/embedder, ни regex query исходного дела не вызываются. Unknown/missing bank возвращает query=null с причиной, foreign chat404, invalid subject422; running analysis возвращает ожидание. Новый report/DOCX включает актуальную статистику и ограничения; старые artifacts неизменны. Сбой refilter откатывает весь command и не расходует idempotency UUID.

Полный T13 ещё требует user editor/history/source picker, корректной UTF16→codepoint selection/retry/stale UX, DOCX выбранной исторической версии и оставшихся presentation labels. Техническая реализация повторного отбора не является экспертной юридической приёмкой.
