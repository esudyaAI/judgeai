# Протокол автозапуска

Каждые 5 часов запускается новая сессия Claude. Она не помнит прошлые — вся память в `docs/TASKS.md` и git.

## Окружение
- Репозиторий: GitHub `esudyaAI/judgeai` (https://github.com/esudyaAI/judgeai), с 28.10.2026. GitLab `judgeai/judgeai` — старое место, туда больше не пушить и MR не открывать. План читать из `main` на GitHub. Каждый запуск создаёт свою ветку `auto/<Tn>-<короткое-имя>` от свежего `main` и пушит туда код и обновлённый TASKS.md. Если предыдущая `auto/*` ветка ещё не смержена — строй от неё, а не от main. В `main` не пушить и самому не мержить (даже если защита ветки на GitHub не включена); PR открыть можно.
- Работа с git — только на Mac через osascript `do shell script` (в облачном контейнере нет доступа к GitHub и закрыты pip/npm). Рабочая копия для автозапуска — отдельный свежий клон, например `~/judgeai-auto/<Tn>`: `git clone https://github.com/esudyaAI/judgeai.git`. Рабочее дерево пользователя `/Users/alexsho/Documents/05_PROJECTS/LETI/ПРАВО/judgeai` не трогать (там могут быть незакоммиченные правки).
- Push: `git push -u origin auto/<...>` из клона на Mac (https, учётные данные `gh`/osxkeychain). PR: `gh pr create -R esudyaAI/judgeai --draft --base main`. После пуша сверить: `git fetch` и прогнать тесты на запушенном коммите.
- CI — GitHub Actions (`.github/workflows/ci.yml`); статус: `gh pr checks <n> -R esudyaAI/judgeai`.
- Команды на Mac: osascript `do shell script` (PATH: `/opt/homebrew/bin:/usr/local/bin`; длинные процессы: `cd X; nohup cmd > log 2>&1 < /dev/null &`, без `&&` перед nohup). `device_bash` — Linux-VM без доступа к GitHub, для git не годится.
- Тесты: legal_core — `docker run --rm -v "$PWD/packages/legal_core":/core -w /core judgeai-api:latest python -m pytest`; api — `docker compose run --rm api pytest` в отдельном compose-проекте (`-p jai_<Tn>`), не трогая рабочие контейнеры пользователя.

## Правила
0. **Никакого хардкода данных (требование пользователя).** Все данные, которые видит пользователь или на которые опирается анализ, берутся из БД: санкции статей, практика, статистика, списки дел, результаты. В БД данные попадают только импортёром из реального источника с происхождением (url, редакция, дата загрузки). Фронт работает только через API; моки (`VITE_USE_MOCKS`) не попадают в сборку и демо. Фейковые данные допустимы только в тестах (фикстуры). Логика норм УК (как считать ст. 68 и т. п.) — бизнес-правила в legal_core, не данные; конкретные санкции и редакции — данные в БД. Захардкоженное сейчас (фейк LLM как источник результата, моки фронта, санкции в коде) вынести в БД/фикстуры в рамках соответствующей задачи.
1. Одна задача за запуск. TDD: тест → код → рефакторинг. Покрытие ≥ 80%.
2. Не ломать работающее: удаление — только с заглушкой `TODO` и пометкой в журнале.
3. Никаких секретов в коде/коммитах/логах. Ключ LLM — только `.env` (не коммитится).
4. Приватные образцы (`ПРАВО/judgeai-private/`) — не коммитить, не пушить, не цитировать.
5. Не переписывать историю git, не force-push, не мержить в main, не деплоить.
6. Схема БД — только новой миграцией с описанным downgrade.
7. Тест/линтер красный — не коммитить; записать в журнал и оставить задачу `[~]`.
8. В конце: обновить TASKS.md (статус + журнал), запушить, отчёт по-русски: что сделано, что проверено, что не вышло, что дальше.
9. Если Mac недоступен — из облака GitHub недоступен, пушить нечем: записать в отчёт «Mac недоступен» (с причиной) и закончить; задачи «можно без Mac» (T1, частично T5) можно исследовать, но результат сохранить только в отчёте до следующего запуска с Mac.
10. Все задачи `[x]` → отключить свой scheduled task (update_trigger enabled=false) и написать итоговый отчёт.
