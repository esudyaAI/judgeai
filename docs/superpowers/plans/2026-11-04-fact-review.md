# T13 — подтверждение/исправление фактов и версии результата

Статусы и доказательства — только docs/TASKS.md. План подготовлен после чтения CONCEPT_ALIGNMENT C01–C04/C06, TASKS T13/T14, assemble_analysis/runner, segmented extraction, текущего destructive recalculate и reports plan. Требования полного T13 не сужаются до формы редактирования LLM-ответа.

## Проблема и результат

Message.analysis содержит представление и часть наблюдений; sentence/count_statutes/practice и локальные входы правил теряются. assemble_analysis дополнительно читает regex-факты, а для нескольких осуждённых строит отдельные входы, игнорируя глобальные модельные факты. Поэтому исправление extraction.facts или JSON результата само по себе не меняет юридический расчёт.

Нужен один путь подготовки/применения входов для первичного анализа и человеческой проверки. Пользователь видит факт/лицо/источник/цитату, подтверждает, исправляет или оставляет неизвестным. Сохранение повторно применяет существующие правила без LLM/эмбеддингов/поиска. Получается новая неизменяемая версия результата; прежние версии и готовые отчёты сохраняются. Подтверждённые факты не означают подтверждённую законность приговора.

## Границы реализации

1. Извлечь из существующей assemble_analysis подготовку конкретных входов существующих правил и применение правил. Переиспользовать legal_core сущности/функции; не писать второй набор юридических вычислений в review или UI. Сохранить поведение golden tests до добавления редактирования. Отдельно зафиксировать per-defendant входы; нельзя приписывать глобальную цитату любому осуждённому.
2. Версионированный calculation input содержит исходные материалы/их attachment_id, text/original hash, prompt, подтверждённые/конфликтные наблюдения и координаты, типизированные факты по лицам, назначения/единицы/условность/режим, prior convictions и даты, санкции с редакциями/источниками, найденную практику/фильтры и происхождение модели. Не включать пути/клиентские секреты. Сериализация domain dataclasses/enums/dates находится во внешнем adapter; domain/application не импортируют Pydantic/SQLAlchemy/FastAPI.
3. Domain проверяет разрешённый путь факта, лицо, тип/границы/единицы, source hash и точное соответствие цитаты Unicode-координатам. False/0/unknown различаются. Для исправления требуются причина и источник; отсутствие сведений сохраняется как unknown. Подтверждение не восстанавливает произвольно один из конфликтующих machine facts. Человеческое решение применяется в месте фактического потребления входа правила и не перезаписывается последующим regex parsing.
4. Application use case через narrow repository/calculator ports: owner+case lock, compatible completed/current engine input, optimistic base revision, идемпотентность запроса, применение решений, пересчёт существующим calculator, запись новой версии и атомарное переключение текущего result. Никакой сети. Недоступные старые engine inputs требуют сначала нового анализа; не восстанавливать их текущими настройками. Снимок norms/practice сохраняется; изменение факта не подменяет редакцию нормы новой из БД.
5. При изменении фактов не переносить прежние модельные рекомендации/сводку как актуальные: исходный текст остаётся в истории. Практику перепроверять существующими фильтрами на сохранённом candidate pool (включая участников статистики, не только shown10); новый поиск не запускать скрытно. Изменившиеся квалификация/рецидив/назначение не должны получать старые n/перцентили как новое сравнение. Неполнота сохранённой выборки и необходимость нового поиска показываются явно. Подтверждение без изменения значения сохраняет прежние фактические результаты, добавляя только состояние проверки.
6. Source viewer проверки показывает текст/координаты именно base revision. Текущий attachment original можно открывать как исходник этой версии только после совпадения сохранённого byte hash; иначе доступен snapshot text и явное ограничение, а не другой изменившийся файл.

## Данные и миграция0016 (до реализации повторно сверить head)

Новая analysis_revisions: UUID id, owner_id, chat_id, source_message_id (FK к существующим сущностям; cascade вместе с делом/источником), per-message version, base_revision_id, kind machine/human/legacy, nullable calculation_inputs JSONB +hash, result JSONB +hash, review JSONB (actor_id/time/decisions/reasons/source refs), created_at, client_request_id/payload hash для idempotency. Уникальности (source_message_id,version) и owner/client_request_id для команд с idempotency key. Новая версия сначала получает UUID, result.revision metadata и hash считаются по окончательному JSON без циклической ссылки на собственный hash.

Старые строки не backfill-ить фиктивными inputs/reviewer/model. При первом пересчёте legacy результат архивируется как legacy с inputs=NULL до очистки current result. Новые machine результаты сохраняются вместе с действительными inputs; человеческие версии с ними и решениями. Текущий Message.analysis остаётся совместимым указателем-представлением последней версии (additive revision/human_review), история — из immutable table. Текущий POST recalculate не должен уничтожать последнюю копию old analysis даже при последующем сбое. Существующие reports хранят свои bytes/snapshots независимо.

План миграции: только additive table, сначала isolated DB/parity/roundtrip. Никакой рабочей миграции без отдельного разрешения и backup/restore. Старое приложение игнорирует новую таблицу, SQL downgrade для отката не нужен. Непустой downgrade отказывается до явного архива; private source/results не удаляются автоматически. Account export включает owned revisions, case/account deletion каскадно удаляет только их. Применение/rollback данных и запуск job должны быть транзакционно совместимы с будущей T18 queue.

## API и UI

- GET /api/chats/{chat}/messages/{message}/revisions и /revisions/{id}: owner-scoped история/входы/результат; чужие404, private/no-store.
- POST /api/chats/{chat}/messages/{message}/review: CSRF, base_revision_id + idempotency UUID + решения по стабильным fact IDs/typed values/source coordinates/reasons.409 для stale base/busy/нет пригодного input;422 для невалидного поля/цитаты/лица/единицы. Дубликат той же команды возвращает ту же версию; другой payload с тем же key409. Сбой пересчёта не оставляет частичной версии.
- Отдельные API/state hooks и FactReview panel: лицо/поле/исходное и новое значение, документ/цитата/координаты, подтвердить/исправить/unknown, причина; подтверждение выбранных фактов и ясный остаток непроверенных. Раздельно «факты проверены» и «норма требует юридической проверки». Конфликты/недостаток данных остаются видимыми.
- История версий, просмотр старого результата и DOCX именно этой версии. Форма не рассчитывает сроки/санкции. Loading/empty/failure/retry и защита от двойного submit/потери правок при ошибке. Доступ к legacy истории сохраняется; старые неподдерживаемые inputs не получают фиктивную форму.

## Проверки и приёмка

Golden parity подготовки/расчёта до/после выделения. Domain: корректные/пустые/противоречивые/граничные значения, даты/единицы, разные лица, точные координаты/хеши, false и unknown. Replay сериализованных входов даёт те же checks/imposed/practice без доступа к БД/сети и не зависит от изменённой текущей санкции/корпуса. Проверить все классы поддерживаемых editable facts, включая prior history и назначенные наказания, а не только один LLM guilt.

API: исправленный факт реально меняет соответствующую проверку, неподтверждённое остаётся unknown, human decision не перезаписан regex, cross-user отрицательные тесты, CSRF, stale base, duplicate delivery, ошибка калькулятора/rollback, recalc failure с сохранением старой версии, old report bytes неизменны, cascade только своего дела, populated migration guard/account export. Frontend behavior/typecheck/build, actual API desktop/mobile flow, ручной просмотр цитат/истории/DOCX. Утверждённая юристом матрица УК/УПК/временной применимости и приёмка всё ещё нужны; технические тесты их не заменяют.

## Source binding contract/4

До разрешения human command новые machine inputs сохраняют review_sources metadata: хеши исходных текстов, стабильный номер/label осуждённого и допустимые Unicode-codepoint интервалы в оригинальных документах. Полные тексты повторно не копируются: берутся из frozen kwargs.document_texts/prompt. Один источник вопроса index=-1 допускается только при single-person context. При multi-person разрешены только явно отнесённые существующим scoper заявления/operative blocks; коллективное назначение без индивидуальной атрибуции не становится разрешённым индивидуальным блоком. Сохранённая карта не пересчитывается текущим parser при human command.

Domain валидирует doc index/subject/index types (bool не int), SHA-256 текста, точные start/end/quote и вхождение всего диапазона в разрешённый interval. Не нормализовать Unicode/пробелы/пунктуацию; цитата из другого места с теми же словами не проходит по позиции. Этот контроль подтверждает происхождение/область, не смысловую юридическую истинность факта.

Новые inputs/4 обязательны для trusted review source context. Старые/1,/2,/3 остаются читаемыми/replayable; им не приписывается историческая карта текущего parser. Для них требуется новый анализ до human command. SQL-миграция не нужна, review_sources — additive JSON metadata в0016; старые rows/reports не backfill-ятся.

Owner-scoped read endpoint .../revisions/{id}/sources предоставляет зафиксированные документы и subject ranges для выбора цитаты. Endpoint .../revisions/{id}/evidence/check проверяет предложенную цитату без записи версии/изменения статуса проверки человеком (CSRF для POST). Ни successful source check, ни чтение source context не означают подтверждение фактов человеком. Команда human revision далее обязана повторить те же проверки на сервере, не доверяя прошлому successful check клиента.

## Следующий implementation slice — настоящая human command

Источник теперь проверяется отдельно; следующая работа должна дать actual corrected-fact→changed-check, а не ещё один read API. Use case под case lock: проверить owned source, повтор idempotency по(owner,client_request_id) с digest(chat,message,base,decisions), busy/current completed/current revision/result hash/current engine, load frozen context/4, allowlisted field specs, strict values/операции и reason, validate_evidence для каждого known confirm/correct, применить clone inputs, replay существующим calculator, сохранить human revision + current Message одной транзакцией. Нельзя принимать произвольный JSON path или actor/time из клиента. Same key+same payload возвращает старую версию даже при потерянном ответе; same key+другой payload409. Чужие404; stale base/busy/legacy409; invalid type/source/field422. Сбой после INSERT откатывает всю human revision.

Confirm сохраняет существующее значение (False не теряется); неизвестное нельзя подтвердить. Correct требует типизированное значение и source proof; unknown требует причину и не превращается в False/0/пустую историю. Каждый публичный fact ID однозначно определяет subject, caller subject index не может переназначить поле. Guilt обновляет оба связанных prepared model/category-guilt входа, не включает regex fallback. Приоритет человеческого решения сохраняется в действительном входе нормы, не только в output JSON.

Catalog должен охватить legal guilt/category/history/prior fields, sentencing/regime/sex/served/circumstances/exceptions/terms/qualifications/dates/conditional/probation и структурные добавления недостающих приговоров/эпизодов. Индексы и overlap-правки должны быть безопасны; unknown нельзя реализовывать удалением всей prior history с последующим выводом «судимостей нет». Ненулевые обязательные core fields (например term kind) и boolean conditional требуют явного unknown-гейта затронутых проверок; запрещено молча оставлять прежнее known значение или подменять неизвестное False. Эти детали ещё не реализованы, их нельзя скрыть за поддержкой одного guilt.

При changed value удалить устаревшие LLM variants/recommended term и явно отделить старую сводку от актуальных фактов. Для практики переиспользовать существующие compare_draft_with_practice/FindSimilarPrecedents/core filters на read-only frozen candidate-pool adapter с embedding port=None-result, без сети/БД/новой модели. Новый query строится из исправленных prepared facts/sentence и новых checks, не regex исходного текста. Это ограниченный повторный отбор сохранённой выборки с явной оговоркой о необходимости нового поиска, не повтор поиска по всему корпусу. Смена qualification не должна получать прежнюю неподходящую sanction/scale; использовать только подходящую замороженную редакцию или «не проверено». Не копировать юридические расчёты/статистику во второй implementation.

Новая review metadata — частичная проверка фактов пользователем, а не юридическое одобрение. Source preflight handler остаётся read-only. Human proof/actor/reason/old/new/evidence входят в immutable row и account export. Затем UI field catalog/source picker/history, строгая конверсия JS UTF16 selection→codepoints, retry с тем же command UUID, stale error без потери формы и DOCX именно выбранной версии. На всё нужны настоящие API/negative/desktop/mobile проверки.

## Расширение editable sentence contract (до реализации)

В existing inputs/4 additive prepared sentencing metadata: explicit unknown_fields для обязательного kind/main/conditional, frozen per-count guilt для ст.69 и established=true|false|null у circumstances. Не хранить неизвестное как False/0; latent core value при unknown whole-term никогда не передавать зависимой проверке/не показывать как установленное. Known kinds с неизвестной quantity хранят amount/unit=null. Explicit unknown conditional должен показываться null и останавливать ст.73/58; другие независимые count checks сохраняются. Unknown dates/rules очищают соответствующие core поля, stage unknown помечается stage_conflict.

Terms редактируются атомарным объектом kind/amount/unit, с проверкой комбинаций до core DTO; qualification разбирается существующим parse_qualifications (одна особенная статья), reference обновляется вместе с текстом. Смена qualification не использует прежнюю root sanction/model maximum/qualification; применяются только совпадающие frozen count sanctions, иначе insufficient. Все уже существующие count/additional/final/intermediate/unserved/joined/credited термы доступны; missing priors/count/additional/circumstances добавляются allowlisted /new field с typed object, не произвольным path. Индексы старых entries не сдвигаются. Unknown circumstance сохраняет запись с established=null, исключается из known calculation и отмечается предупреждением. Unknown prior field/record не удаляет судимость. Новый неполный count не получает inferred completed stage или conditional=false.

## Fine credit и повторный отбор сохранённой практики

Fine-credit record редактируется как typed object scope/count_index/original_amount/reduced_amount/released/status; только count scope принимает существующий индекс, суммы конечные/неотрицательные, reduced не выше known original, released — strict bool. Unknown whole record сохраняет latent запись/индекс, explicit marker скрывает old released/amounts в presentation и не допускает её как known вход практики. Никаких дней→рубли, неизвестное не подставляет False/0. Существующая проверка законности зачёта остаётся insufficient, не становится verified из-за human correction.

Review calculator сохраняет исходный per-subject PracticeReport bank в additive root metadata перед первым refilter. Последующие исправления используют тот же полный retained bank, а не суженную выборку предыдущего refilter. Только own subject pool; global multi-person practice не присваивается человеку. Query собирается из исправленных prepared sentence/circumstances/новых legal checks; старый frozen fabula используется только для прежнего текстового контекста. Неизвестная conditional/qualification/fine credit не превращается в False или другую квалификацию: refilter честно недоступен до уточнения. Stateless in-memory store отдаёт только frozen StoredCard и no-network embedder возвращает None; существующий compare_draft_with_practice повторяет core filters/ranking/statistics на всех сохранённых кандидатов. Старые LLM variants/recommendation не восстанавливаются. Явно показать ограничение retained pool и то, что старые исключённые корпусом кандидаты не возвращаются; новые корпусные данные/веса/редакции не читаются.
