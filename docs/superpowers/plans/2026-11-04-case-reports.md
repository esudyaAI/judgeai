# Неизменяемые отчёты и DOCX — T14

Статусы/проверки/остатки вести только в docs/TASKS.md. Это контракт реализации, не подтверждение готовности.

## Результат и границы

Пользователь сохраняет завершённый анализ в отчёт, открывает личный раздел отчётов/историю версий и скачивает DOCX. Сохранённые данные и готовый DOCX не пересчитываются после изменения правил, провайдера или исходного сообщения. Результат остаётся предварительным, если факты/нормы не прошли проверку человеком; неизвестные provenance/редакции старых результатов явно неизвестны. Другие форматы экспорта не добавляются.

## Данные и миграция

Следующая ревизия после0013 —0014_case_reports. Таблица case_reports: UUID id, owner_id, chat_id, source_message_id, последовательная внутри дела version, snapshot JSONB, snapshot_sha256, docx_data BYTEA, docx_sha256, created_at. Уникальности (chat_id,version) и (chat_id,snapshot_sha256); одинаковое повторное сохранение возвращает существующий снимок. Удаление дела/источника каскадно удаляет его отчёты; удаление другого дела их не затрагивает. Список/просмотр/скачивание проверяют владельца сервером.

Снимок содержит исходный analysis JSON, доступные материалы (attachment_id, имя, extracted text, SHA-256 текста, SHA-256 байтов оригинала при наличии, статус чтения/страницы), provenance использованных правил/моделей/промптов и состояние проверки человеком. Материалы берутся из сохранённого extraction.documents; для старых v1 — из однозначного request_message_id. Отсутствующие файлы/неизвестный набор не подменяются актуальными документами другого анализа; явно отмечаются ограничения. Серверные пути в ответ/артефакт не попадают.

Для новых анализов provenance записывается при выполнении, а не восстанавливается по текущим settings при создании старого отчёта. Модели/промпты/редакции legacy, которых нет в источнике, остаются неизвестными. Старые сообщения/analysis не backfill-ятся и не удаляются: отчёты создаются по запросу пользователя. Миграция только добавляет таблицу. Перед рабочей миграцией нужен отдельный backup/restore и разрешение; downgrade при непустой таблице останавливается до явного архива. Предыдущий код совместим с дополнительной таблицей, SQL downgrade для отката приложения не требуется.

## Слои и API

Domain/application определяют снимок, ошибки и narrow repository/document-hash/export ports без HTTP/SQLAlchemy/python-docx. Infrastructure обеспечивает owner-scoped SQL/блокировки, безопасное чтение хеша существующего файла и DOCX builder; presentation валидирует DTO и отображает ошибки. Расчёты наказания не дублируются: отчёт копирует сохранённые значения/объяснения/цитаты.

- POST /api/chats/{chat_id}/messages/{message_id}/reports — CSRF, только завершённый совместимый assistant-result,201 для нового/200 для повторного снимка;409 при незавершённом/пустом результате. Создание сериализуется блокировкой дела; материал не снимается во время pending/running работ, способных его менять.
- GET /api/reports?chat_id=&limit=&offset= — только свои, свежие версии первыми, limit1..100/default50, offset>=0.
- GET /api/reports/{id} — сохранённый результат и metadata материалов без серверных путей; история берётся тем же списком с chat_id.
- GET /api/reports/{id}/docx — готовые сохранённые байты, private/no-store, фиксированное безопасное имя файла с версией,404 для чужого/отсутствующего. Сбой генерации не оставляет полусохранённого отчёта.

DOCX формируется один раз при создании через python-docx в отдельном thread. A4/поля2см, Times New Roman12, читаемая иерархия заголовков. Содержимое: версия/дата/проверка человеком и ограничения; материалы/хеши; назначенные наказания; проверки по лицам с нормами, источниками и цитатами; практика с n/фильтрами/перцентилями; рекомендации и provenance. Полный исходный текст сохраняется в снимке, но не дублируется целиком в DOCX. Старый DOCX отдаётся без запуска builder/правил.

## Интерфейс

Отдельная ReportsScreen и API/state hooks. Маршруты /app/reports и /app/reports/{id}; Sidebar получает действие «Отчёты». В результате завершённого сообщения существующая загрузка становится «Скачать DOCX»: создаёт снимок и скачивает его артефакт, блокирует повторный клик, показывает ошибку. В списке/просмотре доступны версия, дата, дело, ограничения и скачивание; пустое состояние, ошибка, повтор загрузки. Просмотр старой версии не вызывает пересчёт. Верстка использует существующие компоненты/стили, desktop/mobile и reduced-motion правила.

## Приёмка

Два пользователя: чужие list/get/download/create отклоняются. Старый отчёт/байты/хеши не меняются после recalculate, смены engine/settings/правил или создания новой версии. Повтор create не дублирует версию; разные снимки получают разные версии. Empty/pending/legacy/отсутствующий файл и builder failure обработаны без выдуманных данных и утечек. Каскадное удаление и migration parity/upgrade/downgrade-guard проверены. DOCX открывается и визуально проверяется через существующий локальный LibreOffice/PDF preview, без внешней отправки. Frontend behavior/typecheck/build и реальные desktop/mobile flows обязательны перед завершением этапа.

Полная T13 (подтверждение/исправление отдельных фактов с версиями) и юридическая приёмка не заменяются сохранением отчёта; их недоступное состояние остаётся «не проверено», а не автоматически «подтверждено».
