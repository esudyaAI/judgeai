# Поиск чатов и рабочий профиль

Область: собственные чаты; профиль, фото, пароль, реальные сеансы, экспорт и удаление собственных дел. Будущие функции (2FA, email-уведомления, автоудаление, региональные фильтры/экспорт DOCX) не имитировать переключателями. Уточнение охвата отправлено владельцу; при отсутствии ответа реализуются основные существующие действия.

Архитектура: HTTP валидирует/переводит ошибки, application use cases оркестрируют профиль/пароль/сеансы через repository port; SQL и файлы в infrastructure. Переиспользовать существующие hash_password/check_password, сессии, CSRF и owner-фильтры. Новую юридическую логику не добавлять.

Схема: 0009_user_profiles, новая таблица user_profiles с user_id PK/FK users ON DELETE CASCADE и JSONB payload. Не менять старые записи/схемы дел. Профиль отсутствует = пустые поля; backfill не нужен. Перед prod-миграцией — backup БД. Откат приложения совместим с сохранённой таблицей; downgrade удаляет только user_profiles (сначала экспортировать профили). Рабочие миграции/деплой не выполнять.

Фото: ограниченный data URL PNG/JPEG/WebP, максимум 256 KiB декодированного изображения, без SVG/произвольных URL. Не загружать чужой контент из URL.
Пароль: требовать старый пароль, существующая политика длины, ограничивать попытки, аннулировать остальные сеансы. Сеансы: показывать дату создания/истечения без токенов, адресов и выдуманных устройств; идентификатор для отзыва — производный от текущего токена и конкретного сеанса, не сам bearer/хеш.
Данные: экспорт JSON своих чатов/сообщений/извлечённого текста/анализа (без оригиналов и серверных путей, явно указать формат); удаление своих дел после отдельного подтверждения и проверки пароля. Незавершённый анализ блокирует удаление. Исходные файлы удалять только в upload root и если больше нигде не используются. Общую практику и чужие записи не менять.
Проверки: cross-user отрицательные, CSRF, старый пароль/лимиты, ревокация, roundtrip профиля/фото, owner search и литеральные wildcard, экспорт и удаление. Frontend test/typecheck/build, осмотр desktop/mobile если browser host доступен. Реестр статусов — только docs/TASKS.md.

Интеграция 28.10.2026: обе независимые 0009 объединены пустой ревизией 0010_merge_profiles_defendants, старые ID не переписываются. Перед штатным обновлением workflow делает pg_dump -Fc в закрытый backups и проверяет каталог pg_restore --list; при ошибке обновление не начинается. Откат приложения сохраняет таблицу профилей; откат БД только отдельно после экспорта/backup.
