# Удаление отдельного чата

Расширить существующий owner-scoped delete_cases необязательным chat_id: тот же lock и проверка активного анализа, каскад БД и безопасная очистка исходников. Узкий application port для удаления, SQL adapter вызывает общий механизм, HTTP переводит not found/busy в 404/409. Без миграций. Общая практика и чужие/остальные собственные чаты не меняются.

UI: отдельная доступная кнопка-корзина в строке рядом с кнопкой открытия, confirmation dialog браузера с названием и предупреждением об удалении сообщений/вложений; блокировка повторного запроса, ошибка в панели, после успеха список и поиск обновляются, активный удалённый чат закрывается. Во время анализа/отправки удаление заблокировано на клиенте и сервере.

Проверки: owner isolation, CSRF/anonymous, missing/busy, каскад и безопасная очистка общих файлов; transport/SSR, typecheck/build и Chromium desktop/mobile с отменой/подтверждением, reload и активным чатом. Статусы только TASKS.md.
