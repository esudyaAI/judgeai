# Контроль внешней обработки

Контракт технического этапа T9/T17. Статусы, результаты проверок и незавершённые требования — в TASKS.md.

## Разрешение на передачу

Прикладные LLM-клиенты и Jina получают решение через два параметра оператора:

```dotenv
EXTERNAL_PROCESSING_APPROVAL_ID=recorded-decision-reference
EXTERNAL_PROCESSING_ALLOWED_ENDPOINTS=https://approved.example.invalid/v1
```

Это пример формы конфигурации, не разрешение на обработку. По умолчанию ссылка отсутствует, список пуст: внешний вызов отклоняется до HTTP, без подмены результата фиктивным. Пользователь HTTP API не может разрешить передачу своим запросом или заголовком. Основной LLM, фолбэк и Jina проверяются независимо по точному base URL; завершающий `/` несущественен. Userinfo, query и fragment в адресе запрещены. Одобрение одного адреса не разрешает другой, в том числе фолбэк.

Ответственный за данные должен зафиксировать допустимые обработчики и категории материалов, место хранения и сроки хранения/удаления у системы и провайдера. Сама строка ID не доказывает наличие такого решения. Agent не выставляет разрешение автоматически и не назначает сроки хранения.

## Локальное преобразование

Application получает spans из локального детектора. Перекрытия объединяются, известные компоненты распознанных имён распространяются на повторы/формы в разных частях выбранных материалов. Псевдонимы имеют случайное пространство на вызов; одинаковая исходная строка внутри вызова получает одинаковую замену. Таблица соответствий существует только в памяти процесса и не добавляется в запрос, журнал или общий кэш.

В LLM отправляются замаскированные system/user строки, а возвращённые строковые значения и ключи JSON восстанавливаются локально. Неизвестная замена или неоднозначное восстановление отклоняются. Модель получает инструкцию не угадывать скрытые даты, возраст и правовые факты. После восстановления продолжают действовать проверки буквального совпадения цитат и юридические проверки по локальному оригиналу; наличие цитаты не доказывает правильность интерпретации.

Полные выбранные материалы сканируются до оконного извлечения. Границы модельных сегментов не разрезают распознанный идентификатор. Literal-окно наказания, найденное в источнике, расширяется до полного пересекающего его поля; неоднозначный/слишком большой фрагмент не отправляется. Восстановленная цитата по-прежнему должна принадлежать исходному проверяемому окну, иначе назначение не принимается. `ANALYSIS_VERSION=analysis/3`, версия таких чтений `punishment-window/2`.

Jina получает контекст исходных материалов через явный materials-параметр (в том числе API прецедентов, fallback и shared upload/reembed). Контекст не добавляется в HTTP body: он нужен только для локального распознавания имён и восстановления целых полей на границе фрагмента. Векторные adapters сохраняют timeout/model_name при привязке контекста. Выделение свежей фабулы не разрезает известный идентификатор на границе prefix.

Jina получает стабильную нейтральную редакцию (`скрыто`), без случайных namespaces: маскирование выполняется до нормализации и ограничения длины. Ключ модели кэша помечен `::privacy-redaction/1`; фактический model ID в запросе не меняется. Старые векторы сохраняются и не смешиваются с новым преобразованием; автоматической пересборки/сетевого reindex нет. Локальный fastembed не отправляет текст внешнему модельному API и сохраняет прежний ключ.

## Кэш и журналы

Новые приватные чтения окон сохраняются только внутри дела, повторно используются в нём и удаляются с ним. Старый общий кэш не читается для приватного анализа и не удаляется автоматически. Миграция, backfill/rollback и ограничения описаны в PRIVATE_WINDOW_CACHE_MIGRATION.md. Рабочую БД этот технический этап не мигрирует.

Из журналов удалены тела ответов, произвольные сообщения transport/fallback ошибок и квалификации из ответа модели. Usage учитывается только при корректном неотрицательном целом значении; retry после ошибки схемы содержит типы и известные позиции ошибок, без input/context и произвольных ключей. SQLAlchemy скрывает bind-параметры. Идентификаторы задач, этапы, длительность, статусы и размеры остаются доступны. Низкоуровневые transport-классы — адаптеры для изолированных тестов; прикладная сборка использует guarded factory, а не raw клиент.

## Область применимости

Синтетическая матрица покрывает распознаваемые ФИО/инициалы/контекстные латинские имена, некоторые формы/регистр известных имён, телефоны, email, длинные цифровые идентификаторы, паспорт/СНИЛС/карты, VIN/госномер, даты, адреса и URL. Это обратимая псевдонимизация известных шаблонов, а не доказанное полное обезличивание произвольного судебного текста. Возможны пропуски неизвестных имён, OCR-искажений и иных идентификаторов, а также избыточные замены. Утраченное для модели значение не восстанавливается угадыванием.

Карточки версии precedent-card/12 учитывают безопасную границу фабулы; refresh/reindex требует отдельного явного запуска и не выполняется техническим этапом. Старые карточки, excerpts и чанки могут содержать ранее обрезанные или нестандартные идентификаторы. Новая версия векторного кэша не является приёмкой корпуса: перед разрешением внешних вызовов нужны отдельный offline-аудит/подготовка материалов и решение ответственного (T17/T19). Юридическая корректность, качество реальной модели и поиск проверяются отдельно (T20/T29). Полный аудит хранения/удаления, резервное восстановление и TLS также не следуют из успешных MockTransport-тестов.

Откат приложения не должен использоваться для обхода запрета передачи; рабочее включение требует отдельной приёмки. Тесты используют fake либо MockTransport и синтетические решения, не отправляя реальные дела провайдеру.
